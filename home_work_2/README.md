# Три лампы — один вход

Три выключателя находятся в коридоре,
три лампы накаливания — за закрытой дверью. Определить соответствие нужно,
войдя в комнату только один раз. Автор: Юшков Владислав.

## Запуск

Нужен Python **3.10+** с Tkinter и графическим рабочим столом.
Открой терминал в папке `home_work_2`.

Windows, PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py(если из той же репы, то просто python main.py)
```

Если команды `py` нет, используй `python` в первой строке. Активировать
окружение не обязательно. При следующих запусках нужна только последняя команда.

macOS/Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

Tkinter проверяется командой `python -m tkinter`. На Windows он обычно входит
в установку Python с python.org; на Linux может потребоваться пакет `python3-tk`.
После установки зависимостей интернет приложению не нужен.

## Как играть

1. До входа управляй тремя выключателями в коридоре. Связь с лампами случайна
   и в каждой новой попытке выбирается заново; та же комбинация может повториться.
2. Время идёт в реальном темпе. Кнопки **«+ 30 секунд»** и **«+ 60 секунд»**
   мгновенно добавляют модельное время, чтобы не ждать у экрана.
3. Нажми **«Войти в комнату»**, когда закончишь подготовку. Вход только один:
   выключатели и ожидание блокируются, свет и температуры становятся видимыми.
4. Для каждой лампы выбери её выключатель в выпадающем списке.
5. Нажми **«Проверить соответствие»**. Проверка одна; после неё программа
   показывает результат и настоящую проводку.
6. **«Новая попытка»** сбрасывает время, охлаждает лампы до начальной температуры,
   закрывает комнату и заново выбирает проводку.

Пока дверь закрыта, карточки не показывают ни температуру, ни включённость ламп.
На момент входа создаётся неподвижный снимок: его можно спокойно изучать,
лампы на нём больше не остывают. Это учебное упрощение, а не второе посещение.
Незаполненные или повторяющиеся номера не расходуют проверку: исправь ввод.
Полный допустимый ответ, даже неверный, завершает текущую попытку.

## Решение загадки

1. Включи выключатель **1**.
2. Нажми **«+ 60 секунд»**: его лампа успеет нагреться.
3. Выключи **1** и включи **2**.
4. Сразу войди в комнату.
5. Горящая лампа относится к **2**, выключенная горячая или тёплая — к **1**,
   выключенная холодная — к **3**.

В интерфейсе есть кнопка подсказки с этим алгоритмом. Если войти без подготовки,
например со всеми выключенными холодными лампами, наблюдений будет недостаточно
для однозначного вывода. Это допустимый проигрышный сценарий.

## Температура

Это приближённая учебная модель, а не расчёт конкретной марки лампочки:

| Параметр | Значение |
| --- | --- |
| Температура комнаты и начальная температура | 22 °C |
| Предельная температура включённой лампы | 85 °C |
| Постоянная времени нагревания | 45 секунд |
| Постоянная времени остывания | 120 секунд |
| Подпись «Холодная» | Ниже 30 °C |
| Подпись «Тёплая» | От 30 до 50 °C, не включая 50 |
| Подпись «Горячая» | От 50 °C |

Используется экспоненциальная формула:

```text
T_новая = T_цель + (T_старая − T_цель) × exp(−секунды / tau)
```

При включении цель равна 85 °C, при выключении — 22 °C. Поэтому лампа
нагревается постепенно и остывает медленнее, чем нагревается. После 60 секунд
нагрева температура составит примерно **68,4 °C**. После выключения и ещё
30 секунд ожидания — примерно **58,1 °C**.

Температура показывается с одним знаком после запятой; состояние «горит»
определяется выключателем, а не температурой. Только что включённая лампа
может уже гореть и при этом оставаться холодной.

## Тестирование

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

На macOS/Linux используй `.venv/bin/python`. Только логика без окна:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_model.py -q
```

Проверяются все **шесть** вариантов проводки, правильная стратегия решения,
нагрев, остывание, независимость температуры от дробления времени на шаги,
запрет повторного входа и доступа к скрытым данным, проверка ответа и
отклонение некорректных входных значений.

GUI-тесты используют настоящие переключатели, кнопку входа и кнопку проверки.
Они проверяют скрытие состояния до входа, полный сценарий решения, исправление
повторяющихся номеров и сброс. На Linux без `DISPLAY` GUI-тесты пропускаются;
ошибки самого приложения не маскируются. Для тестов используется одно скрытое
окно, состояние сбрасывается перед каждым сценарием.

### `main.py` — запуск

Создаёт `PuzzleApp` и вызывает `mainloop()`: цикл обработки событий окна.
При импорте файла окно само не открывается.

### `model.py` — правила и физика

`Phase` обозначает три этапа: подготовка, наблюдение после входа и завершение.
Переходы разрешены только вперёд. `LampPuzzle` хранит случайную проводку,
состояния выключателей, температуры и прошедшее время.

- `set_switch()` меняет один выключатель до входа.
- `advance()` рассчитывает температуры за переданный интервал.
- `enter_room()` расходует единственный вход и создаёт снимки `LampObservation`.
- `observations` возвращает снимки только после входа.
- `submit()` проверяет соответствие. Ответ задаётся в порядке ламп: сначала
  номер выключателя лампы 1, затем лампы 2 и лампы 3.
- `solution` раскрывает правильное соответствие только после проверки ответа.

`LampObservation` — неизменяемый объект с номером лампы, состоянием света
и температурой. Его свойство `thermal_state` формирует подпись о нагреве.
Модель не импортирует CustomTkinter: её можно проверять без графического экрана.

### `app.py` — интерфейс

`PuzzleApp` создаёт окно, коридор с выключателями и комнату с тремя `LampCard`.
`LampCard.hide()` скрывает наблюдения, `reveal()` показывает их после входа.
Выпадающие списки включаются только после открытия комнаты.

`_tick()` вызывается каждые 200 мс через `after()`. `_sync_time()` измеряет
реально прошедшее время через монотонные часы `perf_counter()` и передаёт
его модели. Перед каждым переключением сначала учитывается время со старым
состоянием: новая лампа не получает нагрев за время, когда ещё не горела.

`_wait()` добавляет модельные секунды без блокировки интерфейса.
`_enter()` открывает комнату и отключает подготовительные действия.
`_submit()` проверяет заполнение списков и передаёт ответ модели.
`_reset()` создаёт новую игру и восстанавливает исходный вид.
При закрытии окна отложенный таймер отменяется в `destroy()`.

Ни `sleep`, ни фоновые потоки не используются. Вся работа идёт в цикле
событий GUI. Первая задача из соседней папки для запуска не требуется.


## Если возникла ошибка

- `No module named customtkinter`: установи `requirements.txt` тем же Python,
  которым запускаешь `main.py`.
- `No module named pytest`: установи `requirements-dev.txt`.
- Ошибка Tcl/Tk или дисплея: проверь установку Tkinter и наличие графической сессии.

Виджеты: [CTkSwitch](https://customtkinter.tomschimansky.com/documentation/widgets/switch/)
и [CTkOptionMenu](https://customtkinter.tomschimansky.com/documentation/widgets/optionmenu/).
